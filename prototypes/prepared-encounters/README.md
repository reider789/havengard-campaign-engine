# Подготовленные встречи Переломья

Это запас боевых данных для оставшихся ответвлений после Солеварни. Подготовка
не меняет канон, текущий бой G5, ресурсы, часы, опыт или награды.

Основной файл: [perelomye/catalog.json](perelomye/catalog.json). В нём 19 карточек
(18 из бестиария и отдельный явно подготовленный вариант двух охранников
компании), 13 шаблонов комнат, исходные полные тексты, три полных досье боссов,
конечные составы, устройства, опасности, добыча и правила переходов.

Карточки C14 и C18 — переиспользование уже существующих существ; новых скатов
или нового распорядителя подготовка не создаёт. Нейтральные персонажи не
назначаются врагами. V4 — условный шаблон конфликта о дороге, а не предсказанное
событие и не обязательное место будущей схватки.

## Запуск

Нужна закреплённая копия `reider789/rin_dnd` на коммите
`153b8447b0d77f700f006eb40b9725f1ac943e33`. Сборщик проверяет все 55 хешей
из существующего `engine-lock.json`; файлы общего ядра не изменяются.

```sh
python tools/build_prepared_encounter.py \
  --engine-root /path/to/rin_dnd \
  --room T8 --output /path/to/output/rehearsal.html
```

Это **репетиция** с демонстрационными местами героев и сегодняшним снимком
партии. Её нельзя считать будущим началом боя или импортировать в канон.
Для L5 и V4 расстановка намеренно не придумана; нужен `--deployment`.

При реальном первом столкновении сначала обновить каноническое состояние,
проверить последний сыгранный эпизод, часы, оставшихся существ и ресурсы.
Потом передать актуальный deployment:

```sh
python tools/build_prepared_encounter.py \
  --engine-root /path/to/rin_dnd --room T8 \
  --deployment /path/to/deployment.json --story \
  --output /path/to/output/battle.html
```

Deployment содержит `source_revision`, `source_state_sha256`, `source` с
основанием реальной расстановки, `population_verified:true`,
`initial_deployment:true`, `heroes` и `enemies` в штатном формате сценария.
Все четыре героя остаются под управлением игрока. Неподтверждённые новые
существа, повторные ID и устаревший снимок отклоняются. L5 принимает только
`L5-C05-3`/`L5-C05-4` при их реальном присутствии, а не автоматически обе смены.
V4 принимает `faction-roven`, `faction-itta`, `faction-demar`, до двух
`faction-guard-1..2` (C05_company) и до шести `faction-worker-1..6` (C03/C04).
Присутствие каждого нужно подтвердить. Для V4 разрешён явный `battlefield`
с реальной геометрией. Городская стража — другой состав, не подкрепление компании.

Если сыгранные траты ещё не попали в основной снимок, разрешены явные
`resource_overrides:{hero:{pool:current}}` и `resource_override_source`.
Это не восстанавливает и не списывает ресурсы в каноне само по себе.

При возвращении **загрузить сохранение предыдущей встречи**, включая ПЗ,
применения, сгоревшие приборы, активации и погоду; не собирать всё заново с
полными ПЗ. Новый сюжетный G5 этим сборщиком запрещён: там уже готовится
реальный бой, нужно продолжать его существующее сохранение.

## Что исполняется

`gm-assist.js` — единая панель и ограниченные обработчики поверх штатного SDK.
Профили и сцены остаются данными. Для следующего экземпляра уже подготовленного
противника код не пишется. Нет скрытого автоматического управления героями;
автоходы врагов в этих сборках остановлены, решения принимает ведущий.

Для ведущей в чате есть `tools/prepared_gm_turn.js`: он принимает полный
checkpoint и запрос с `session_sha256` и явными командами SDK, проверяет их
и пишет **новое** сохранение. Запрос готовит ведущая, не игрок. Мост запрещает
управлять героями и отвечать за них в окнах реакций; при таком окне нужно
дождаться решения игрока. Собственный ход врага и его специальные действия
исполняются из готовых данных, без нового кода. Команда:

```sh
node tools/prepared_gm_turn.js /path/to/rin_dnd \
  /path/to/session.json /path/to/gm-request.json /path/to/next-session.json
```

Штатное ядро разрешает атаки, обычные перемещения и атаки по возможности,
защиты/реакции героев, заклинания из своего реестра, урон, сопротивления,
состояния, лозы C09, сохранение и журнал. Дополнение исполняет смешанные
пакеты урона, конечные боеприпасы, ослабление роя, яд нужной длительности,
пылевое облако, замены атак захватом/толчком, легендарные очки и окна,
устойчивости с ценой, переходы фаз, активацию конечных оболочек, реакции
парирования/щита, перезарядку и броски заранее подготовленных действий/арены.

**Автоматизация подготовленных встреч.**

`prepared-runtime.js` исполняет особые заклинания Эссы через штатные окна
Контрзаклинания; применения и ячейки остаются отдельными. На инициативе 20
сначала разрешается прежняя область, затем ведущий выбирает источник и новую
точку. Цели вычисляются при ударе по действительным позициям, высоте и укрытию.
Гибель зверя не отменяет природную грозу, разрушение опоры не заземляет её.

Приборы имеют настоящие КД/ПЗ: доступны оружие, Огненный снаряд, Палящий луч,
Цепная молния, Рассеивание магии и взаимодействие действием. Проверка и расход
действия исполняются загрузчиком. Инструменты и цепь берутся из доступного
инвентаря, подавление арсенала заканчивается в конце следующего хода заклинателя.

Числовые точки задаются как `H6@20` (высота в футах) либо `-2,5@10`
(мировые координаты за рисунком). Путь — соседние клетки через пробел.
Режимы: шаг, полёт, лазание, плавание; учитываются общий бюджет, площадь,
реакции и падение. Объявление дыхания сохраняет числовую ось; поворот и конус
проверяются при применении. Необязательные реакции героев всегда выбирает игрок.
Ведущий управляет противниками, их реакциями и отметкой арены.

Это исполнитель описанных арен, а не универсальная симуляция любого мира.
Новая Тишина импортируется только после реального разрешённого эффекта с
источником и сроком; новая магия герою не выдаётся. Неописанные сюжетные
взаимодействия, например аварийная линия старого C18, остаются конкретным
решением ведущего по действительной сцене. Старые сохранения без runtime
открываются в прежнем режиме с решениями ведущего, без выдуманной миграции.

## Совместимость и продолжение

Пакет требует `perelomye-gm-assist-v1` и `perelomye-runtime-v1`; обычный загрузчик отклонит его.
Внутренний `engineVersion:30.9.0` у сохранения — **барьер сериализации этого
дополнения**, не утверждение о выпуске новой версии upstream. Он не даёт старой
странице молча проигнорировать решения/очередь. Открывать сохранения только в
сборке с этим дополнением. Текущий штатный G5 и его entrypoint не изменены.

Полное сохранение содержит состояние всех противников и устройств. После боя
проверить обычный отчёт ресурсов и отдельно записать сюжетный исход,
оставшихся существ, приборы и реальные награды. Репетиции не импортировать.
Ни XP, ни добыча автоматически не начисляются. `boss.xp` включает указанную
конечную свиту; `creature.xp`/`profile_xp` относится к отдельному существу.

## Проверки и обновление

```sh
python tools/verify_prepared_encounters.py --engine-root /path/to/rin_dnd
```

Проверка собирает все заданные расстановки и тестирует сохранения, специальные
действия и защитные ограничения. Она не играет реальную сцену. Полёт и
пространственное решение ведущего не объявляются автоматически проверенными.

Для обновления после редактирования источника Drive:

```sh
python tools/prepare_perelomye.py /path/to/reviewed-source-3.2.json
```

Сначала сверить изменения сюжета и актуальную игру, затем пересоздать каталог,
просмотреть diff и повторить проверки. Отчёт со списком модулей и ограничениями:
[docs/PERELOMYE_COMBAT_PREPARATION.md](../../docs/PERELOMYE_COMBAT_PREPARATION.md).
