# Сюжетный бой Хейвенгарда: переход из повествования в чат

**Режим:** полностью внутри ChatGPT. Репозиторий — источник канона и сборки, **не игровой сайт**.
Этот протокол применяется, когда по повествованию действительно начинается столкновение. Он **не создаёт** никакого сюжетного боя заранее.

## Что делает ведущая, без ручных действий игрока

1. Сверяет последнюю подтверждённую сцену и дату в летописи, `state/_campaign-state.json`, `rules/_campaign-rules.json`, актуальные карточки четверых персонажей. Не объявляет бой без сюжетного основания.
2. Устанавливает, какие противники реально вступили в бой, кто виден, есть ли скрытые герои, где находится каждый участник, стены/укрытия/труднопроходимая местность. Определяет инициативу **по правилам и фактическим броскам**. Никакого автоматического переноса врагов со «Старого моста».
3. Даёт сцене уникальный стабильный `battle_id`, понятное `name`, `chronicle_anchor`, краткое `narrative_context`, `source_revision` строго из текущего канона.
4. Ведущая сама сохраняет JSON карточки сценария в **`prototypes/chat-combat/story/active-scene.json`** средствами подключённого GitHub, без просьб к игроку писать или править JSON. **Файл не существует до настоящего сюжетного столкновения.**
5. Workflow `build-story-combat.yml` проверяет данные и создаёт отдельные `prototypes/chat-combat/story/story-chat-battle.html` и `story-manifest.json`. Это **один самодостаточный HTML**, внутри которого лежат текущие канонические ресурсы и сценарий. У него нет запросов к GitHub во время боя.
6. Ведущая предоставляет в чате панель запуска с **контрольной суммой и размером из `story-manifest.json`**. Если в клиенте невозможно выполнить большой HTML прямо из сообщения, игрок выбирает подготовленный HTML-файл в панели чата (не на отдельном игровом сайте). Это единственное пока остающееся ручное действие, обусловленное ограничением среды ChatGPT.
7. Интерфейс **автоматически** создаёт поле данного `battle_id`, с предусмотренными противниками и ходом первого по инициативе. Игрок не настраивает арену. После сообщений чат использует сохранение только этой же сюжетной сцены, если совпадают ID и исходная ревизия канона.

## Минимальный формат данных

Эти данные **готовит ведущая, а не игрок**. Пример ниже намеренно искусственный и существует только для объяснения формата, **не каноническая засада**.

```json
{
  "schema_version": 1,
  "kind": "story",
  "battle_id": "chapter15_scene3_fight01",
  "source_revision": 27,
  "name": "Тестовый бой — не летопись",
  "narrative_context": "Только пример структуры. В настоящем бою описывается подтверждённая сцена.",
  "chronicle_anchor": "ТЕСТ — искусственная точка, не канон",
  "heroes": {
    "yar": {"cell": "B6", "initiative": 11},
    "daphne": {"cell": "B7", "initiative": 16},
    "lyutobor": {"cell": "C5", "initiative": 14},
    "rada": {"cell": "C4", "initiative": 22, "hidden": false}
  },
  "walls": ["F3", "F4"],
  "rubble": ["E4"],
  "enemies": [
    {
      "name": "Условный противник",
      "cell": "H5",
      "hp": 33,
      "ac": 15,
      "initiative": 13,
      "attack": {"bonus": 5, "count": 1, "die": 8, "flat": 3, "range": 5},
      "saves": {"STR": 2, "DEX": 1, "CON": 2, "INT": 0, "WIS": 0, "CHA": 0},
      "abilities": []
    }
  ]
}
```

Клетки A1–K8, 11×8, шаг 5 фт. От одного до 20 врагов. В боевой карточке врага нельзя оставлять обязательные числовые поля пустыми. Неизвестные уникальные способности, реакции, заклинания и предметы нельзя объявлять автоматически рассчитанными: требуется конкретный подтверждённый обработчик или решение ведущей.

## Проверки и безопасное продолжение

- **Учебное состояние не переносится** в сюжет: старые страж и арбалетчик не участвуют в сцене и не попадают в очередь инициативы.
- При восстановлении сессии сравниваются `battle_id`, `sessionKind=story`, исходная `source_revision`. Другая сессия не подменяет текущую.
- **Сброс** сюжетной схватки требует отдельного подтверждения. Сброс возвращает к сцене, а не к «Старому мосту».
- Если враг получил наибольшую инициативу, его первый ход обрабатывается по обычной боевой механике с возможностью реакции героев.
- Последствия боя выгружаются как **`havengard-combat-outcome-draft`** с `battle_id`, `chronicle_anchor`, ревизией и всеми расходами. Это не изменение канона.
- Ведущая проверяет, что нет повторного списания, что исходная ревизия канона не устарела, что учтены раненые, добыча, смерти и сюжетные последствия. Затем предлагает игроку подтвердить итог и **лишь после подтверждения** записывает через штатную систему кампании и продолжает художественное повествование.
- Пока сражение ещё идёт, новые данные GitHub не перетирают сохранение боя.
- После завершения/фиксации нового сюжетного боя `active-scene.json` нужно заменить при следующем столкновении либо вывести из активного использования. Старый HTML остаётся исторической сборкой и **не является источником канона**.

## Команды сборки и QA

```bash
python prototypes/chat-combat/build_chat_bundle.py --root . --scenario prototypes/chat-combat/story/active-scene.json --output prototypes/chat-combat/story/story-chat-battle.html
python prototypes/chat-combat/tests/test_bundle.py
python prototypes/chat-combat/tests/qa_v21_story.py
```

GitHub Actions сам запускает сборку при коммите настоящего `active-scene.json`. Изменение канонического состояния вне боя не должно молча менять уже начатую сюжетную схватку.

## Подготовленные ответвления Переломья

Перед созданием новой карточки противника проверить [готовый каталог](../prepared-encounters/README.md) и `prototypes/prepared-encounters/perelomye/catalog.json`. Для поддержанных встреч использовать `tools/build_prepared_encounter.py`: он берёт актуальную партию, готовые карточки и подтверждённую расстановку. Дополнение использует закреплённое ядро, отдельную панель ведущего и `tools/prepared_gm_turn.js`; переносить решения врагов на игрока или просить его редактировать JSON не нужно. Особые заклинания идут через штатные окна контрмагии; инициатива 20, геометрия авторских областей, приборы, числовой полёт и падение исполняются prepared-runtime. Ведущая выбирает действия противников и отметку арены; игрок принимает решения и необязательные реакции четырёх героев. Полный checkpoint сохраняет противников и устройства между посещениями. Текущий G5 продолжать из его настоящего сохранения, не подменять шаблоном.
