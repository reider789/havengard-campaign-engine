## v24 — изоляция состояния и зависимостей обработчиков боя

Новые классы заклинаний и реакций больше не обращаются к свободной переменной `s` и функциям из внешнего лексического окружения. Они получают `CombatStatePort` при создании: метод `getState()` читает **актуальную**, а не старую ссылку на сессию, а `services()` предоставляет конкретные игровые операции (урон, проверки, окно реакции, журнал, отрисовку и т. д.). Все зависимости перечислены на границе интеграции в `engine-v24.html`. Таймер продолжения ходьбы также инъецирован, а не вызывается напрямую из класса.

Проверки: изолированный тест заменяет объект состояния в процессе работы тех же экземпляров обработчиков и проверяет корректную обработку новых и старых сессий; браузерные QA отдельно тестируют заклинания, Руку Бигби, цепочки Контрзаклинания, сохранение/восстановление и поведение в чате. `state/_campaign-state.json` не меняется, формат сессии остаётся `version:12`, `engine-v23.html` сохраняется для отката. Приложения и загрузки файлов от игрока не требуются: шесть модулей и порт компилируются в один автономный HTML.

Граница изоляции честная: до полной миграции основного игрового кода глобальный `s` продолжает существовать **в интеграционном слое**, однако отсутствует как неявная зависимость внутри обоих новых обработчиков. Это не объявляется полным архитектурным разделением всего проекта.

## Запуск в ChatGPT без скачивания файлов — CDN

Проверка в реальном клиенте показала: вызовы `fetch` к `raw.githubusercontent.com` не выполняются, а к `cdn.jsdelivr.net` — выполняются; изображения через внешний CDN тоже загружаются. Поэтому **GitHub остаётся репозиторием**, а AppBlock получает файл движка и графику через jsDelivr CDN.

Графический пакет из 24 изображений теперь **фактически сохранён в репозитории** по адресу `prototypes/chat-combat/art/hayvengard_art_v1.json` (1,57 млн символов). При запуске в чате загрузчик должен получить по CDN два файла: самодостаточный `current-chat-battle.html` и этот арт-пакет. Далее вставить арт в `<script type="application/json" data-hg-artpack>` **до запуска основного скрипта**; `visual_skin.js` сам применяет фон и круглые жетоны на первом отображении. Оба файла можно привязывать к одному проверенному SHA GitHub для воспроизводимости.

Это **не отдельный игровой сайт** и не требует от игрока скачивать или загружать файлы. Предыдущая ручная загрузка JSON в интерфейсе сохранена только как резервный режим. Чтобы избежать подмены посреди боя, используем иммутабельный commit SHA либо сверяем контрольную сумму перед исполнением и не обновляем начатую сессию автоматически.

При переходе к сюжетному бою его HTML сборка аналогично выдаётся через CDN, но с привязанным `battle_id`, а не с учебным «Старым мостом». Не смешивать состояние учебного и сюжетного боя. Непосредственный запуск полного HTML через CDN ещё необходимо проверить в клиенте; успешный запрос маленького текста сам по себе этого не доказывает.

## Художественное оформление поля — графический пакет v1

**Подключено к боевому движку:** `visual_skin.js` автоматически включается в `current-chat-battle.html` и в будущие сюжетные файлы. Он не меняет броски, ПЗ, очередность, линии видимости, перемещение или игровые коллизии.

Художественный пакет `hayvengard_art_v1.json` создан в этой переписке и выдаётся игроку отдельным файлом. В ChatGPT движок не может надёжно выполнять `fetch` к GitHub, поэтому арт импортируется **без сети** через кнопку «Загрузить изображения» в панели «Оформление». При разрешённом браузерном хранилище он запоминается и повторного выбора файла не требует. Он намеренно не включается в контрольную точку боя, чтобы не раздувать сохранение мегабайтами.

**Состав: 24 WebP**: фоны луг/лес/руины/город; круглые портреты Яра/Дафны/Лютобора/Рады, 8 архетипов врагов (воин, разбойник, лучник, маг, волк, орк/громила, нежить, дракон) и 8 типов препятствий (стена, разрушенная стена, завал, частокол, бревно, валуны, куст, колонна).

**Выбор по сцене:** JSON боя поддерживает `theme: meadow|forest|ruins|city`, враг — необязательный `tokenKey: warrior|rogue|archer|mage|wolf|orc|undead|dragon`; для отдельных клеток препятствий — `obstacleSkins: {"F3":"barricade","E4":"boulder"}`. Важны только те препятствия, которые ведущая уже пометила в `walls` или `rubble`: картинка сама не создаёт стену или труднопроходимую клетку. Отсутствующие ключи подбираются автоматически по роли и расположению.

**Учебный бой:** один случайный фон при создании; в любое время переключается вручную без затраты игрового действия. Настройки фона сохраняются в состоянии боя. **Сюжетный бой:** из поля `theme` от ведущей, не случайный, и не заменяет сюжетные правила.

Запуск локально: `python prototypes/chat-combat/tests/qa_art_skin.py` после стандартной сборки; регрессия проверяет неизменность ПЗ, действий и канонической ревизии при смене графики.

1. **Громовая волна:** принудительное перемещение производится только при провале спасброска ТЕЛ. Одной цели не применяется дважды.
2. **Произвольные противники:** карточка с именем, координатами, инициативой, КД, ПЗ, атакой (бонус, число кубов, размер куба, постоянная часть, дальность), спасбросками и описательными особенностями. Сортировка инициативы не сбрасывает текущий ход. Набор ролей и атаки берутся из данных, не жёстко закодированы под стража/арбалетчика.
3. **Сохранение и восстановление:** контрольная точка в JSON содержит раунд, инициативу, позиции, ПЗ, ресурсы, дым, эффекты, инвентарь, историю, дополнительные карточки врагов, необработанный бросок и незавершённую цепочку реакций; импорт не обнуляет `pending` и `attackFrame`.
4. **Хранение в чатовом интерфейсе:** каждое изменение состояния на экране передаётся в доступный host binding без повторной отправки одинакового состояния, при этом JSON-экспорт остаётся резервным способом переноса между разговорами.
5. **Безопасное разделение источников:** каноническое состояние не меняется ни при одном действии учебного боя; новая ревизия GitHub используется только при **запуске новой сессии**, а не посреди схватки.
6. **Регрессия v19:** повторные проверки Контрзаклинания, Руки Бигби, реакций и ловушек сохранены и повторно выполнены против v20.

## Что не является доказанным и требует внимания при реальной игре

- **Встроенный клиент ChatGPT:** запуск всего self-contained HTML внутри AppBlock **не проверен на клиенте пользователя**. Работа в Chromium и успешность GitHub Actions не гарантируют, что ChatGPT отрисует весь код. Нельзя повторять старую попытку удалённой загрузки JavaScript.
- **Действительно уникальные способности новых монстров:** вводятся в справочник/карточку, но их особая механика не создаётся автоматически из текста. Для неизвестных эффектов требуется ведущая, прежде чем списывать ресурс или считать урон.
- **Абсолютная полнота D&D 2024:** нет математической гарантии всех комбинаций правил, укрытий, концентрации, снаряжения, контроля и цепочек реакций. Проверены конкретные регрессионные сценарии, не все возможные.
- **Долговременное сохранение в ChatGPT:** тест вызова host binding в браузере пройден; персистентность между отдельными сообщениями зависит от клиента. JSON-экспорт и импорт — поддерживаемая переносимая контрольная точка.

## Запуск и контроль

Перед новой боевой сценой: открыть `current-manifest.json` и убедиться, что его `source_revision` совпадает с `state/_campaign-state.json`. Если нет — дождаться GitHub Actions или вручную пересобрать пакет: `python prototypes/chat-combat/build_chat_bundle.py --root .`.

Самостоятельные регрессионные проверки с установленными Playwright/Chromium: `python prototypes/chat-combat/tests/qa_v20_state.py`, `python prototypes/chat-combat/tests/qa_v20_rounds.py`. Проверка сборщика без браузера: `python prototypes/chat-combat/tests/test_bundle.py`.

Не переносить учебные расходы, ПЗ и позиции в канонический `state/` без явно подтверждённого результата сюжетного боя.

## История v19

# Хейвенгард — актуальная чатовая боевая сборка v19

**Только для использования в ChatGPT.** Не меняйте GitHub Pages или `prototypes/combat/app/`. Исходный HTML/JS: [engine-v19.html](engine-v19.html). Указатель: `entrypoint.json`.

Канон: `state/_campaign-state.json` и `rules/_campaign-rules.json`. При проверке ревизия **27, Г1М8**. Учебная сцена начинается с хода Дафны; расход ресурсов из тренировки **не переносится в канон**.

## Что добавлено в v19
- **Реакции атаки с сохранением одного броска:** Protection до атаки, затем автозащита Щитом Дафны, затем Знак Стража против крита, Плащ Яра, Невероятное уклонение Рады или Ответный удар после промаха. При цепочке урон применяется один раз после решений, поддерживаются пауза и продолжение при атаках по возможности.
- **Контрзаклинание D&D 2024:** окно при наблюдаемом колдовстве в 60 фт, реакция и ячейка III круга, спасбросок Телосложения заклинателя против СЛ противодействующего. На провале действие/реакция не возвращается, но ячейка прерванного заклинания возвращается. Поддерживаются вложенные Контрзаклинания разных противоборствующих заклинателей по LIFO; одна реакция на персонажа. Учитывается правило «не более одной ячейки заклинания в один ход», включая реакцию в собственный ход. Реализовано как для вражеского колдовства, так и для основных заклинаний Дафны, если есть вражеский контрзаклинатель. Дополнительные маги тестовые, не канонические враги.
- **Рука Бигби (2024):** действие и ячейка V круга при создании, концентрация 1 мин, КД20, ПЗ как максимум ПЗ Дафны; команда при создании и бонусное действие на последующих ходах. Перемещение до 60 фт **в рамках той же команды**; Кулак 5к8 силовым (атака +11), Толчок (СИЛ СЛ19 до 30 фт), Захват (ЛОВ СЛ19), Сдавливание захваченной цели 4к6+5 и Прикрытие (+2 КД от линий через руку). Урон по самой руке и исчезновение при окончании концентрации учитываются.
- **Предметы без численных характеристик в каноне:** сигнальные ракеты и металлические ловушки, а также вновь обнаруженные предметы можно установить на поле **только после явного утверждения временных параметров** (дальность, длительность, СЛ, формула урона); никакие значения не выдумываются и не записываются в Campaign Engine.

## Проверки и воспроизведение
Скрипты с Playwright находятся в `tests/`:
- `qa_chat_v19_extended.py` — 88 клеток, критический удар → Знак Стража → Невероятное уклонение, вражеское Контрзаклинание, создание и атака Рукой Бигби, сигнальная ракета.
- `qa_chat_v19_counter_party.py` — заклинание Дафны против вражеского Контрзаклинания; цепочка «маг колдует → Дафна контрзаклинанием → второй маг контрзаклинанием».
- `qa_chat_v19_modes.py` — захват, сдавливание, прикрытие Рукой Бигби, утверждённая временная ловушка и её срабатывание.

Запуск в системе с Chromium и Playwright: `python prototypes/chat-combat/tests/qa_chat_v19_extended.py` (аналогично остальные два). В нашей тестовой среде все три скрипта пройдены без ошибок JavaScript. Проверены отдельные ветви, но это **не доказательство корректности всех возможных сочетаний D&D 2024**.

## Границы готовности
- Нестандартные новые предметы без утверждённого описания нельзя честно сделать полностью автоматическими без решения ведущего; режим ручного утверждения — осознанная защита канона.
- Движок содержит универсальные оконные реакции для перечисленных событий, но не утверждает, что произвольные способности будущих существ уже имеют обработчики.
- Работоспособность self-contained HTML проверена в Chromium, **открытие всего v19 непосредственно во встроенном AppBlock в клиенте пользователя ещё не подтверждено**. Не загружать удалённый JavaScript в чат: этот механизм ранее дал ошибку.
- Не подменять текущие ресурсы уже идущего боя данными из более свежей ревизии без начала новой тренировочной сессии.

# Хейвенгард — боевой движок в чате

## Назначение

ЭТО ОТДЕЛЬНЫЙ РЕЖИМ ДЛЯ CHATGPT. Исходный код: `engine-v18.html` (самодостаточный HTML+CSS+JS).
НЕ ОБНОВЛЯТЬ веб-сайт GitHub Pages и файлы `prototypes/combat/app/` для развития чатового боя. Сайт не является игровым интерфейсом кампании.

## Источники
- Канон: `state/_campaign-state.json` и `rules/_campaign-rules.json`.
- Актуальная ревизия при проверке: **27 / Г1М8**.
- Дополнительный справочник: `prototypes/combat/character-capability-registry-g1m8-v1.json`.
- При новом бое ассистент читает канон через GitHub-коннектор, создаёт снимок и **встраивает** его в панель. JavaScript загружается непосредственно в сообщении (никаких fetch() для удалённого кода); браузерный сетевой запрос из ChatGPT не считается гарантированным.
- `engine-v18.html` работает без удалённых скриптов; без переданного снимка включает офлайн-учебные значения и обязан явно сообщать о них. Новые способности из GitHub появятся в справочнике, но для их уникальной механики нужен обработчик.

## Выполнено и проверено в браузерной регрессии
1. Поле 11×8 (88 клеток), инициатива и карточки без смены активного героя.
2. Блокировка недоступной точки для Громовой волны без расхода ячейки.
3. Огненный шар по F6 и автоматическая Скульптура для Яра, Лютобора, Рады; ПЗ получателя изменяются, союзники остаются целы.
4. Следующий ход Лютобора, включение Священного оружия.
5. Следующий ход Яра, «Приманка и смена» с соседом и обмен координатами.
6. «Несгибаемость» Яра: урон ждёт решения после проваленного ЛОВ-спасброска; проверены две ветви, затем продолжается обработка остальных существ.\n7. JS синтаксис (`node --check`), браузерная консоль — без ошибок в перечисленных сценариях.
8. Дополнительные подсистемы присутствуют в исходнике: область конуса, многоцелевые эффекты, часть редких заклинаний, перемещение руки, состояния от контроля, реакции Precision/Riposte, приемы и расходники. **Наличие обработчика не равно тесту всех ветвей.**

## Что действительно автоматизировано
- Базовые атаки, боеприпасы, часть манёвров Яра и реакций защиты.
- Дафна: заговоры, Волшебная стрела, Палящий луч, Огненный шар, Громовая волна, Туманное облако, Замедление, Высшая невидимость, Конус холода, Удержание чудовища, Дверь в измерение, части Руки Бигби и Сферы бури, косметические заклинания.
- Лютобор: Благословение, Щит веры, Лечение ран, Малое восстановление, Героизм, Подмога, Мантия крестоносца, Божественная кара, Священное оружие, часть аур и прочих подготовленных заклинаний.
- Рада: Скрытая атака, ядовитый/опрокидывающий/отступательный Хитрый удар, бонусные действия, часть артефактных свойств.
- Учёт части зелий, огня, дыма и яда, перемещение, сохранение/экспорт учебной сцены.

## НЕ ГОТОВО — обязательно проработать до объявления «все способности полностью реализованы»
- **Пауза/продолжение после спасброска** уже реализованы и проверены для «Несгибаемости» Яра при поражении областными заклинаниями (две ветви — принять провал или перебросить). **Не реализованы полностью** общий случай реакций на любое заклинание/эффект, Counterspell на вражеское колдовство, и произвольная последовательность нескольких реакций.
- Полное соответствие D&D 2024 для произвольных боевых комбинаций: концентрация и отсроченные спасброски, контекст условий зрения/укрытия, временные ПЗ, дополнительная атака от Haste, статус лишения реакции и критические попадания парализованного противника. Некоторые из этих ветвей частично обработаны, но не проверены исчерпывающе.
- Полноценная Рука Бигби (альтернативные действия), Сфера бури, взаимодействие с предметами окружения, манёвры со свободным перемещением союзника.
- Проверка условий использования всех боевых предметов, а также «Сигнальная ракета»/«Металлическая ловушка»: их параметры отсутствуют в подтверждённом каноне; придумывать урон/СЛ нельзя. 
- Возможность запускать **тот же** 100k-символьный движок как встроенную панель непосредственно в ChatGPT ещё не подтверждена клиентским тестом. Самостоятельный HTML работает в Chromium, но нельзя повторять неудачный remote-JavaScript-loader.
- Безусловное обновление текущего боя из GitHub недопустимо: изменения канона влияют на **новую** боевую сессию, а не перезаписывают локальные ПЗ уже идущей.
