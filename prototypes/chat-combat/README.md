# Хейвенгард — боевой движок в чате (v25)

## Как используется

Игрок **ничего не загружает вручную** и не открывает отдельный сайт. Код хранится в GitHub и автоматически собирается в один автономный `current-chat-battle.html`; сюжетные бои привязываются к ревизии канона. Правила работают без сетевого JavaScript и внешних серверов. Сохранения версии 12 поддерживаются, источник канона в бою не изменяется. Встроенная панель ChatGPT требует проверки в том клиенте, где идёт игра: браузерная регрессия не равна подтверждённому запуску AppBlock.

## Архитектура

- `engine-v25.html` — интеграция, механика оставшихся простых действий и компоненты интерфейса.
- `core/dice.js`, `core/journal.js`, `core/conditions.js`, `core/battlefield.js` — отдельные компоненты расчёта.
- `core/state_port.js` — получение актуального состояния и явных зависимостей.
- `core/spell_resolver.js`, `core/reaction_resolver.js` — сложные заклинания и цепочки реакций.
- `core/dom_renderer.js` — дифференциальная перерисовка клеток (не трогает неизменившиеся элементы).
- `core/persistence.js` — сохранения: не более одной отложенной проверки за цикл, сравнение сериализованных данных, повторная передача канонических справочников исключена, если они уже встроены и имеют ту же ревизию.
- `visual_skin.js` — визуальное оформление. Изображения автоматически загружаются по фиксированному адресу CDN, кэшируются при возможности и никогда не входят в состояние боя. Если сеть недоступна, поле остаётся полностью функциональным в штатном оформлении. Одна сетевая загрузка JSON-графики при отсутствии кэша; основная логика не использует сеть.
- `build_chat_bundle.py`, `build_inline_payload.py` — создание и проверка единого HTML и сжатого пакета.

## Тесты и ограничения

GitHub Actions выполняет сборку, синтаксис JavaScript, изолированные тесты модулей и браузерные тесты на сценарии 4 героев и расширенные группы врагов, прерывания и восстановление реакции, Бигби, спасброски, журнал, визуальные эффекты. `tests/qa_v25_perf.py` измеряет скорость и объём сохранений и контролирует сохранение DOM-узлов. Порог производительности задан мягко, чтобы CI на разных машинах не давал ложных ошибок; метрики в логе служат основой для будущих сравнений.

История версий и старые технические решения перенесены в `HISTORY.md`. Архивные исходники v21–v24 сохранены. Отдельный сайт и канонический мастер-файл не обновляются.

## Проверка запуска

Новая игра: использовать `current-chat-battle.html`, проверить `current-manifest.json` и ревизию `state/_campaign-state.json`. Продолжение игры: восстанавливать контрольную точку той же сцены без повторной инициализации ресурсов. Художественный пакет подключается автоматически; при отсутствии сети работать со штатными иконками.
