# Подключение общего боевого ядра

Общее ядро поставляется из `reider789/rin_dnd`, версия 30.2.0, API пакетов 1. Конкретный коммит и хеши исходников закреплены в `engine-lock.json`. Отдельная копия ядра в этом каталоге не создаётся. CI получает именно закреплённую версию, проверяет её файлы, запускает независимую кампанию и читает актуальные карточки Хейвенгарда.

Это подготовленное подключение и проверка совместимости, а не завершённая миграция всех способностей. Действующий интерфейс `prototypes/chat-combat/` остаётся рабочей версией Хейвенгарда. Не следует собирать сюжетный бой с новыми профилями, пропустив неподдержанные способности.

Для проверки локально получите исходники указанного в lock коммита в отдельную папку и выполните:

```sh
python tools/check_shared_combat.py --engine-root ../rin_dnd --output /tmp/havengard-combat-audit.json
```

Проверка не меняет state и не применяет результаты тестовых боёв. `--require-ready` дополнительно запрещает переход, пока полный перенос не подтверждён. Отчёт — инвентаризация механик, а не автоматическая сертификация способности по совпадению названия. Новый обработчик с проверками добавляется в общий движок, затем обновляется lock; обе кампании смогут использовать одно исправление.

На момент подключения канон Хейвенгарда имел ревизию 29, старый реестр возможностей — 27. Аудит берёт названия механик из актуальных `character_sheet.combat_reference`; старый реестр служит для обнаружения отставания. Требуют переноса манёвры и ресурсы воина, ауры и реакции паладина, заклинания и особенности волшебника, оставшиеся особенности разбойника и магических предметов. Примитивы Extra Attack, Sneak Attack, Vex и Nick уже есть, но их наличие не делает весь профиль готовым.

Описание переносимого формата: `docs/CONTENT_PACKS.md` в закреплённой поставке ядра. Пример `examples/portable/border-watch.json` показывает новых героев и авторского противника, подключаемых только данными.
