# Общее боевое ядро Хейвенгарда

Текущий выпуск — 30.5.2, API пакетов 1, источник `reider789/rin_dnd`. Коммит и контрольные суммы закреплены в `engine-lock.json`. Действующий настольный интерфейс собирается из этого ядра; отдельной копии правил здесь нет.

`party-pack.json` формируется адаптером `tools/build_party_combat_pack.py` из актуального канона. `reviewed-profiles.json` содержит проверенные механики карточек, обязательные способности, подготовку и атаки. `migration-audit.json` сравнивает их с пакетом и ресурсами; изменения механики требуют проверки. Неизвестный обработчик подготовленного действия блокируется общим компилятором.

Все четыре героя, текущая магия, классовые действия, защитные реакции и настроенные боевые предметы перенесены. Отдельно проверены полные бои партии, восстановление на решениях, расходы и повторный импорт на копии кампании. Сюжетная история от тестов не изменяется. Неизвестное количество боеприпасов и неподтверждённые компоненты не создаются автоматически.

Исправления 30.5.1 сохраняют смерть, стабилизацию и счётчики умирания через итог и следующий бой. Благословение, статусы и временные ПЗ скакуна переносятся вместе с ним; Помощь и Героизм истекают по игровым часам. Общая схема SDK отклоняет повреждённые эффекты и призывы до записи канона. В браузере явно выбираются владелец прекращаемой концентрации, одно состояние для Малого восстановления, природа и оплата скакуна, пассажир Двери в измерение и атака объекта с видимыми ПЗ. Кулак Бигби использует общие защитные реакции. Полный список: `rin_dnd/docs/CORRECTNESS_30_5_1.md`.

В 30.5.2 исход боя определяется после всей цепочки событий. Итоговый снимок на одном времени снимает истёкшие усиления; пространственная магия сохраняет своё поле, координаты и позиции участников. Адаптер строит и проверяет настоящий следующий бой на копии до подтверждения транзакции. Новая карта не перемещает Руку Бигби или зону автоматически: сначала требуется явное завершение эффекта либо согласованное размещение. Исправлены усиления ответных/ускоренных атак, последовательные подготовленные реакции, типизированный урон одного попадания, движение после освобождения и замена/исчезновение скакуна. Рассеивание выбирает существо, объект или эффект; Защитная связь завершается по своим условиям.

Архив браузера ограничен, имеет индикатор заполнения и выгрузку/удаление/восстановление. Текущий бой защищён; большое прохождение можно явно скачать и удалить из браузера перед новым. Учебные прохождения имеют разные ID. Контрпримеры и проверки: `rin_dnd/docs/CORRECTNESS_30_5_2.md`, `tools/test_shared_boundary.js`, `tools/test_shared_handoff.py`.

```sh
python tools/check_shared_combat.py --engine-root ../rin_dnd --require-ready
python tools/build_shared_combat.py --engine-root ../rin_dnd
python tools/test_shared_handoff.py ../rin_dnd
python tools/test_shared_browser.py
```

Настольный запуск — отдельная ссылка на `prototypes/chat-combat/desktop-battle.html`. Плоская арена не заменяет решения мастера о высоте, новых свойствах, социальных иллюзиях и действиях, меняющих сцену. Ограничения и справочные предметы перечислены в проверенных профилях. Новые заклинания и классы добавляются обработчиками с проверками в общем репозитории, затем обновляется закреплённая версия.
