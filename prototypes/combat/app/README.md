# Хейвенгард — тактическая карта v13

## Канон и данные

Источник истины — **только** `state/_campaign-state.json` в публичном репозитории `reider789/havengard-campaign-engine`. Летописи, состояния и расчёты канонической кампании не изменяются действиями в учебном прототипе.

Для интерфейса:
- `havengard-battle-v13.html` — **основной** код боевого интерфейса.
- `runtime/latest.json` — автоматически генерируемый справочник (кэш), не источник истины.
- `build_runtime.py` — преобразует текущие канонические записи в манифест.
- `.github/workflows/build-combat-runtime.yml` — обновляет кэш после изменения состояния.
- `.github/workflows/deploy-combat-ui.yml` — собирает и публикует сайт через GitHub Pages (требует одноразового включения Pages).

## Как обновляются способности и инвентарь

1. При открытии v13 браузер запрашивает **публичный** `prototypes/combat/app/runtime/latest.json` и **непосредственно** `state/_campaign-state.json` из main через `raw.githubusercontent.com` без токена.
2. Кэш содержит категории способностей и предметов; из текущего канона поверх него берутся ПЗ, доступные ресурсы, количество предметов и новые строки `character_sheet.combat_reference`.
3. Если кэш ещё не обновился, живые данные `state/_campaign-state.json` всё равно имеют приоритет при наличии сети.
4. При недоступности обоих источников интерфейс **явно показывает предупреждение**, использует лишь учебный резервный снимок и не утверждает, что данные актуальны.
5. Для новых способностей, не имеющих проверенного обработчика боевого движка, интерфейс показывает справочную карточку **без изменения ресурсов или выдуманного эффекта**.

Важно: хранение исходного кода в GitHub и актуальное считывание данных решены отдельно от задачи полного автоматического исполнения всех индивидуальных способностей D&D.

## Сайт GitHub Pages (одноразовое включение)

В GitHub открой Settings → Pages → Build and deployment → Source → **GitHub Actions**. После успешного запуска workflow `Deploy Havengard Combat UI` сайт будет доступен на `https://reider789.github.io/havengard-campaign-engine/`.

Пока Pages не включены или workflow не завершился успешно, **не объявлять сайт опубликованным**. Рабочий HTML также доступен в репозитории и как отдельный файл для открытия в браузере.

Workflow пересобирает манифест из канона и разворачивает HTML, не записывая изменения в `state/`.

## Состояние учебного боя

- Изменённый канонический инвентарь используется при **новом** учебном бою, но не переписывает ресурсы внутри уже идущей сессии.
- `Сохранить бой` — состояние в браузере (`localStorage`) или в связанном состоянии интерактивного блока, если доступно. Это **не коммит**.
- `Экспорт JSON` / `Импорт JSON` — перенос сессии и резервное копирование.
- `Новые данные GitHub` — обновление источника после сохранения сессии; чтобы принять исходные ресурсы, начать новую учебную схватку.
- Автоматическое сохранение результатов в официальный канон **не включено**; требует подтверждения игрока и проверки.

## Проверки и границы готовности

- Достоверно проверено через связанный GitHub: репозиторий `public`, `havengard-battle-v13.html` и workflow файлы сохранены.
- Проверено в Node.js: синтаксис скрипта и слияние тестовой ревизии 99 с 8 зельями, новой неизвестной алхимией и новой способностью из текущей карточки.
- **Не подтверждено**: настоящий запрос браузера к публичному GitHub (среда тестового браузера недоступна), запуск GitHub Pages workflow, публикация URL.
- Боевой движок **не завершён**: все уникальные заклинания/манёвры, некоторые реакции и сложные сочетания условий требуют доработки.
- Дым 10 фт / 30 фт / 1 мин — прототипный вариант, не утверждённый канон.

## Принятые решения по интерфейсу

Единое поле 11×8, отдельный просмотр каждого героя, смена оружия, зелья/алхимия, передача расходников, визуальные статусы 🔥/🟢, без режима переодевания доспехов и лаборатории защит. Не выбирать решения персонажей за игрока. Результаты учебного боя не переносятся в кампанию без подтверждения.
