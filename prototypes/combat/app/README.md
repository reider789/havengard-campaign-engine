# Хейвенгард: тактический бой и загрузка Campaign Engine

## Статус
**V12 — функциональный учебный прототип. Не каноническая игра и не полный движок D&D 2024.**

### Где код и данные
- `havengard-battle-v12.html` — HTML/CSS/JavaScript, единая карта, атаки, часть реакций, личные панели, зелья, дым, огонь, передача предметов, ручные маршруты, журнал, импорт/экспорт сессии.
- `runtime/latest.json` — генерируемые данные персонажей (не источник истины): предметы, ресурсы, способности, заклинания, сведения из актуального Campaign Engine.
- `build_runtime.py` — генератор манифеста из `state/_campaign-state.json`, реестра способностей и текущих описаний предметов.
- `.github/workflows/build-combat-runtime.yml` — попытка автоматизировать генерацию при обновлениях состояния и реестра.

### Что является источником истины
1. Каноническая игра — `state/_campaign-state.json`, подтверждённые решения и правила кампании.
2. Реестр и старые снимки служат справочником; новые записи из актуального `character_sheet.combat_reference` загружаются отдельно и имеют приоритет при просмотре.
3. Результаты тестового боя не меняют канон автоматически. Не переносить урон, расходы или позицию героя в `state/` без явного подтверждения игрока.

### Схема обновления данных
```
canonical Campaign Engine (GitHub/private)
    -> build_runtime.py (GitHub Actions on push)
    -> app/runtime/latest.json (generated reference data)
    -> HTML battle UI reads manifest at start of combat session
```

В чате доступ к приватному GitHub идёт **через авторизованный коннектор ChatGPT**.
Нельзя использовать публичный `raw.githubusercontent.com` URL и нельзя передавать GitHub-token в JavaScript интерфейса.
Для запуска боя в чате ассистент читает текущие данные через GitHub и передаёт их во встроенную панель (snapshot). Открытая панель **не обновляется сама** без нового источника. Для настоящего браузерного приложения вне чата нужен авторизованный сервер, который отдаёт `runtime/latest.json` по защищённому адресу.

Если UI обслуживается на одном origin с `runtime/latest.json`, он попытается запросить `./runtime/latest.json`. Если файл недоступен — переходит в учебный offline fallback с предупреждением.

Если добавлено новое заклинание, предмет или способность, оно автоматически появляется в справочнике. **Новая механика не исполняется**, пока не добавлен проверенный обработчик. Без обработчика запрещено расходовать ресурсы или придумывать результат.

### Сохранение
- `Сохранить бой` — сохраняет snapshot в текущем состоянии встроенного интерфейса, не в каноническом GitHub.
- `Экспорт JSON` — делает переносимый файл боевой сессии.
- `Импорт JSON` — восстанавливает сессию. При импорте открытое окно реакций сбрасывается для безопасности; предыдущий боевой ход следует проверить вручную.
- Для постоянного хранения результатов в GitHub нужен отдельный контролируемый шаг записи через коннектор после подтверждения игрока. Прототип не должен автоматически менять канон.

### Что проверено
- Отображение 88 клеток, ход Дафны, несколько вкладок, выбор заклинания.
- Выпивание зелья, передача зелья между соседними героями, переключение оружия, передвижение с сохранением кнопки завершения хода.
- Загрузка внешнего `runtime/latest.json`-подобного манифеста в браузере (mock state revision 55), новый расходник с неизвестной механикой и новая способность из каталога.
- `build_runtime.py` с синтетическим состоянием: новые предметы, способности, ресурсы, инвентарь.
- Размещение кода и манифеста в приватном GitHub.

### Что **не** объявляется завершённым
- Полный обработчик всех заклинаний и манёвров 4 персонажей, строгая юридическая логика D&D 2024 для всех краевых случаев.
- Одновременные цепочки нескольких реакций, автоматический контроль всей концентрации, сложные зоны/вертикаль/обзор.
- Автоматический перенос результатов боя в канон.
- Подтверждённый успешный прогон GitHub Actions в настоящем репозитории: файл workflow сохранён, но успех запуска ещё не проверен отдельно.

### UX-решения, утверждённые игроком
- Не показывать отдельный режим `Между сценами`, переодевание тяжёлых доспехов и лабораторию защит.
- Смена оружия доступна в бою с учётом ограничений взаимодействий.
- Герои смотрят собственные эффекты по нажатию, просмотр не меняет ход или цель.
- `Все возможности` не запрещает нестандартное действие; нестандартное требует решения ведущего.
- Дымовая бомба: радиус 10 футов, дальность 30, время 1 минута — **предложение для тестирования, не канон до одобрения**.
- 🔥 горение и 🟢 ядовитые эффекты должны быть видны на жетонах.

## Работа над сценарием
Перед новой боевой сессией читать `state/_campaign-state.json`, реестр, `runtime/latest.json` и при необходимости заново формировать актуальный runtime. Поскольку GitHub приватен, выполнять чтение через коннектор, а не непосредственно клиентским JS.
