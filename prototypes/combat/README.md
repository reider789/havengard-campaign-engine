# Хейвенгард — единая тактическая панель

## Источник правды и запуск

**Канонические сведения:** `state/_campaign-state.json` (текущие ПЗ, инвентарь, боеприпасы, ячейки, боевые карточки), `rules/_campaign-rules.json` (политика решений).
**Проекция:** `prototypes/combat/runtime/latest.json` — только для чтения, автоматически генерируемая из актуального state. Исторические `migrations/` не должны затирать актуальные данные.
**Код игры:** `prototypes/combat/ui/havengard-v12.html`. Исправлять правила и UI именно здесь; не создавать параллельные версии в каждом чате.

### Обновление GitHub

1. Меняйте актуальную запись в `state/_campaign-state.json`. Одна правка источника, без повторного ручного внесения в боевой UI.
2. Workflow `.github/workflows/combat-runtime-sync.yml` пересобирает `runtime/latest.json` при push в main. Требуется, чтобы Actions были разрешены и у GITHUB_TOKEN была возможность записывать содержимое. Это необходимо проверить в настройках GitHub; один факт сохранения workflow не доказывает, что он уже исполнялся.
3. При авторизованной раздаче всей папки репозитория по одному origin движок сначала пытается получить `../runtime/latest.json` с `cache: no-store`. Старый сеанс не перезаписывается данными нового снимка.
4. **В ChatGPT:** репозиторий PRIVATE, поэтому скрипт виджета не имеет доступа к GitHub connector и не может безопасно автоматически читать GitHub API в фоне. Сначала ассистент загружает `latest.json` через подключённый GitHub, затем передаёт содержимое в виджет как `HAVENGARD_RUNTIME` или `__bindings.value.source`. При открытой игре нужен новый вызов синхронизации через чат. GitHub токены никогда не помещать в JavaScript.
5. Для действительно непрерывного автоматического обновления открытой веб-страницы потребуется **авторизованный сервер/OAuth-прокси**, проверяющий доступ и отдающий только необходимые поля. GitHub Pages/public raw приватного репозитория не применять без явного согласия пользователя на публикацию.

### Изменение персонажей

Новый расходник появляется в разделе «Алхимия» из `inventory_catalog`; если его механика неизвестна, он обозначается как требующий ведущего и не расходуется автоматически. Новое умение, добавленное в `character_sheet.combat_reference`, отображается в «Всё», без программного внесения названия. **Новое уникальное действие** не становится работающим от появления текстового описания: нужен проверенный обработчик эффекта, момента срабатывания, цены, условий и целей.

### Боевой сеанс

Это отдельно сохраняемый, **неканонический** объект. Кнопки «Сохранить бой», «Экспорт JSON» и «Импорт JSON» предназначены для сохранения учебного боя; выгрузка в каноническое состояние происходит только после отдельной проверки и прямого решения игрока. Снимок источников имеет `source_revision`, сеанс — `sourceRevision`. После изменения первоисточника активную сессию нужно сверить перед применением: не заменять потраченные ресурсы текущего боя полным складским инвентарём.

### Возможности V12

- Общая доска 11×8, одна фишка на клетку, стены/обломки, маршрут и перемещение по клеткам.
- Ход, предварительный просмотр и подтверждение затрат.
- Основные атаки, огненный шар, доспехи мага, Благословение и несколько защитных реакций.
- Зелья, передача **одного расходника между соседними героями**, свободное взаимодействие (следующее — за действие), переключение доступного оружия.
- Дым с предварительной домашней геометрией 10 футов/1 минута, огонь/яд отображаются значками; тушение действием.
- Персональная панель героя отдельно от действующего персонажа и цели.
- Экспорт/импорт сеанса, журнал. Режим доспехов и лаборатория защит удалены.

### Ключевые оговорки

- Дымовая бомба: числовые параметры в канонической карточке не описаны, 10 фт/30 фт/1 минута — **предложение для тестов**, не утверждённая норма.
- Не все способности 10-го уровня исполняются. Некоторые — только в справочнике; нельзя заявлять, что движок полностью корректно обрабатывает D&D 2024 или готов к каноническим боям.
- Не полностью реализованы: необычные/многоцелевые заклинания и Counterspell, все манёвры/Хитрые удары, точная геометрия/укрытия и высота, конфликт нескольких реакций, специальные зелья/артефакты, некоторые длительности.
- Динамическая подгрузка описаний и ресурсов **не означает динамическую генерацию новой механики**. Неизвестные эффекты не должны списывать ресурсы.

### Пройденные проверки

На 2026-10-11 проверено локально на Chromium: 88 клеток; Дафна выпивает зелье с реальным расходом предмета; передача зелья Дафна→Яр; движение не удаляет кнопки; экспорт состояния; runtime-injection test с ревизией 999, 8 лечебными зельями вместо 3 и новым «Зельем невидимости» и умением — все появились **без изменения UI-кода**. JavaScript синтаксис проверен, pageerror в этих сценариях отсутствует.
