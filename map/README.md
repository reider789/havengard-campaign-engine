# Интерактивная карта Хейвенгарда — связка с Campaign Engine

## Готово

- `map/layout-base.json` — исходные координаты **101 объекта** из принятой схемы v3. Размеры условные, не геодезические.
- `map/template.html` — интерфейс карты: панорама/масштаб, выбор здания, поиск, оборона, население, хозяйство, строительство, перетаскивание.
- `tools/build_city_map.py` — генератор: получает актуальное `state/_campaign-state.json`, сопоставляет здания с 38 рабочими точками и создаёт `map/offline.html` (один HTML-файл для браузера).
- `.github/workflows/build-city-map.yml` — автоматически пересобирает `map/offline.html`, когда в основной ветке меняется состояние или сам шаблон карты.
- `tools/map_layout_import.py` — принимает выгруженный из карты файл планировки, проверяет координаты и готовит обычную **неигровую** транзакцию `city_map_place` для сохранения в движок.

**Важно:** репозиторий приватный. Нет публичной страницы, и HTML не получает токен GitHub. Его нельзя заставлять читать/записывать приватные данные из браузера без отдельного защищённого сервиса авторизации.

## Использование сейчас

1. В приватном GitHub открыть `map/offline.html`, скачать файл через **Download raw file** и открыть локально в браузере.
2. Нажать на здания и пользоваться разделами карты. Их штат, оборудование и основные числа рассчитаны при сборке из действующей ревизии GitHub; это не вручную заполненные данные старой мастер-книги.
3. Для перемещения включить **«Планировка»** и перетащить нужные объекты. Они сохраняются пока **локально в браузере**.
4. Нажать **«Сохранить JSON»**; прикрепить скачанный `heyvengard-layout-for-github.json` к чату и попросить сохранить планировку. ChatGPT через подключённый GitHub оформит проверяемую транзакцию, не изменяющую казну/сроки/население. Затем CI автоматически пересоберёт новую HTML-карту.
5. Вновь скачать `map/offline.html` с актуальной ревизией. Локальные правки, если они остались, можно экспортировать и сопоставить; не использовать старый файл как источник истины.

## Границы возможностей

- Карта — визуальное представление игрового состояния, а не самостоятельный реестр.
- Изменение позиции в режиме планировки **не означает** перемещения построенного здания в сюжете, строительства, заселения или оплат.
- Здания и планировка сохраняются только после отдельного подтверждённого события Campaign Engine. Расходы и игровые даты не изменяются от перетаскивания.
- При переходе к полноценному **постоянно доступному сайту** можно добавить защищённую авторизацию и API; тогда кнопка «Сохранить» сможет отправлять изменения прямо в GitHub, без промежуточного JSON. Публично выкладывать приватный state/GM-факты нельзя.
- Старый v3-файл использовал отдельное localStorage. Если нужно перенести прежние расстановки, выгрузить v3 JSON и загрузить в v4: формат совместим (`app=heyvengard-map-layout`, `version=3`).

**Никаких повторных месячных расчётов:** Г1М8 уже открыт, источником казны и продовольствия служит `state/_campaign-state.json`.
