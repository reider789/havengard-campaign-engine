# Подготовка Хейвенгарда к настоящему бою

События между боями (добыча, покупка, экипировка, замена подготовки
заклинаний, восстановление ресурсов, истощение, потраченное время)
фиксируются **в повествовании и транзакции кампании**. Само поле боя
не должно создавать добычу, варить зелья или выдавать новые вещи.

## Подтверждённая сюжетная операция

Составить JSON с уникальным `event.id`, кратким `event.summary`,
указанием `event.source` (ссылка на эпизод/подтверждение) и картой
`characters`. Например (НЕ применять к живому канону без события):

```json
{
  "event": {
    "id": "STORY-SAMPLE-2026-10-26",
    "source": "Подтверждённое повествование",
    "summary": "Яр надевает латы, Дафна получает ингредиент"
  },
  "characters": {
    "yar": {
      "exhaustion": 1,
      "armor_class": "19 в надетых латах",
      "item_status": {"yar-source-row-47": "Экипированы"}
    },
    "daphne": {
      "new_items": [{
        "id": "sample-ladle", "name": "Позолоченный половник",
        "quantity": 1, "status": "При себе",
        "value_gp": 500, "component_for": "tashasBubblingCauldron"
      }]
    }
  }
}
```

Тестовый сценарий не является получением вещи: он показывает только
формат. Скрипт **создаёт транзакцию, не меняя состояние**:

```sh
python tools/prepare_combat_event.py --request /path/to/story.json --output /tmp/story-tx.json
python tools/campaignctl.py preview --transaction /tmp/story-tx.json
```

Сначала проверить сюжетный источник, списания, количество предметов,
текущий КД и цену компонентов. Только после решения ведущего —
`campaignctl.py commit --transaction /tmp/story-tx.json`.

Уровень истощения 1–5 назначается повествованием. Шестой уровень
считается смертельным: транзакция устанавливает 0 ПЗ и `dead:true`.
Продолжительный отдых снимает один уровень; факт отдыха и его полные
восстановления записываются отдельным подтверждённым событием.

Обработчики дорогих компонентов автоматически обнаружат **только**
подтверждённые предметы с достаточной `value_gp`, названием,
доступным количеством и соответствующей `component_for`. Не
угадывать стоимость по названию. Не помещать неподтверждённые
предметы в инвентарь ради тестов.

## Новые герои и противники

`build_shared_story.py --profiles /path/to/additional-profiles.json`
принимает `{"profiles":{"id":{...}}}`. Карточка должна удовлетворять
строгому контракту `dnd-combat-pack` общего ядра; произвольный скрипт
не выполняется. Назначайте `profile` в `enemies` или в дополнительных
`heroes` сюжетного сценария. Новые **канонические** герои могут
содержать явно согласованный `combat_profile`; прежние четыре героя
пока используют проверенные настройки адаптера (их нельзя молча
заменить чужой примерной карточкой).

## Высота

В `scenario` есть необязательная карта
`"elevation":{"D4":5,"E4":10}` (высота поверхности в футах).
Пока реализованы отображение уступов и безопасный шаг на 5 футов вверх.
Полёт в объёме, свободное падение и полная трёхмерная видимость —
**отдельная следующая механика**, текущие графические метки её
не имитируют.

## Контрольный сюжетный бой

Полноценный бой и импорт **в живой канон** отложены до завершения
всех согласованных доработок ИИ, графики и пространственных правил.
Обычные CI-проверки используют только копии состояния и не считаются
сыгранным событием.
